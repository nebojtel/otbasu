# Защита внутренних полей товаров

Миграция `20260905_product_column_privacy.sql` не применяется автоматически при публикации на Vercel.

## Порядок применения

1. Сначала опубликовать версию витрины, где запрос `products` использует `publicProductColumns`, а не `select('*')`.
2. Убедиться, что товары загружаются на основном сайте.
3. В SQL Editor проекта Supabase выполнить целиком `20260905_product_column_privacy.sql` от имени владельца базы. Скрипт транзакционный и допускает повторный запуск.
4. Обновить открытую ранее витрину: старые вкладки со старым JavaScript и запросом всех полей потребуют перезагрузки.
5. Проверить под публичным ключом: запрос разрешённых полей возвращает активные товары, запросы `note`, `created_by`, `*` и фильтрация по `note` запрещены.
6. Проверить вход сотрудника в админку: чтение черновиков и заметок, редактирование товара должны по-прежнему работать. Обычная авторизованная учётная запись без активной роли сотрудника не должна читать товары напрямую через эту роль.

Витрина использует отдельный анонимный клиент и не заимствует сессию администратора. Публичные настройки и аналитические события этой миграцией не изменяются.

Миграция не удаляет товары, фотографии, заметки или пользователей. Меняются только разрешения чтения и политики таблицы товаров. Не возвращайте общий SELECT для anon ради совместимости со старой вкладкой: обновите страницу.

Проверки разрешений запускаются командой `npm test` в изолированном PostgreSQL (PGlite), без подключения к рабочей базе. Проверка реальных ролей Supabase после применения остаётся обязательной.

Документация: [права на столбцы Supabase](https://supabase.com/docs/guides/database/postgres/column-level-security).
